# Contributing to CamUI-WebRTC

## AI-assisted development

This project is developed with AI assistance. All contributors are expected to understand every line of code they submit — regardless of whether it was written by hand or generated by an AI tool. AI-generated code is welcome, but must be reviewed and understood in full by the contributor before a pull request is opened. "The AI wrote it" is not an acceptable answer to a code review question.

This policy applies to all code changes: new features, bug fixes, refactors, and configuration changes alike.

## Git workflow

### Branches

- `main` holds the released versions. It only changes when a release is made.
- `dev` is the development branch. All changes are merged here first and tested before
  they are released.

Branch from `dev`:

```
feat/<short-description>
fix/<short-description>
refactor/<short-description>
docs/<short-description>
chore/<short-description>
```

### Commit messages

Follow [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add multi-camera gallery filter
fix: resolve gevent double monkey-patch warning
refactor: extract HLS playlist logic into fmp4.py
docs: update camui.service path note in README
chore: bump gunicorn to 23.0.0
```

### Releases

A release is made by merging `dev` into `main` (merge commit or fast-forward, no
squash) and tagging `main` with `make release VERSION=x.y.z`. A fix that cannot wait for
the next release is made on a branch from `main`, merged into `main` and released, and
then merged back into `dev`.

### Pull requests

- Open PRs against `dev`. A check rejects PRs against `main`; the only exception is the
  release merge from `dev`. If GitHub proposes `main` as the base branch, change it to `dev`.
- Use the PR template — fill in all sections honestly.
- Run all tests before submitting; all cases must pass:
  ```bash
  make test
  ```
- Keep PRs focused: one logical change per PR.
